## Naming Conventions

**Files:**
- Lowercase with underscores: `memento.py`, `db.py`, `demo.py`, `__init__.py`
- Internal only, no suffixes (no `_test.py`, `_utils.py`)

**Directories:**
- `.planning/` prefix indicates internal tooling
- No subdirectories within package root (flat structure)

**Classes:**
- PascalCase: `Memento`, `DB`

**Functions:**
- snake_case for public/module-level functions: `log_retrieval()`, `get_ghosts()`, `corpus_health()`
- snake_case with leading underscore for private helpers: `_now()`, `_hash_query()`, `_days_ago()`, `_ts_to_date()`, `_vec_to_bytes()`, `_bytes_to_vec()`

**Variables:**
- snake_case: `doc_id`, `filename`, `retrieved_at`, `engagement_rate`, `query_hash`, `embedding_vec`
- Abbreviated in loops: `r` (retrieval), `e` (engagement), `d` (document), `did` (doc_id), `ts` (timestamp)
- Constants in module scope: `SCHEMA` (uppercase for schema string)

**Methods in Memento class:**
- Public ingestion: `log_retrieval()`, `log_engagement()`, `log_source_update()`, `register_document()`
- Public analysis: `get_ghosts()`, `get_duplicates()`, `get_obsolete()`, `get_stale_embeddings()`, `get_suspects()`, `corpus_health()`
- Public reporting: `report()`, `cleanup_report()`, `to_dataframe()`
- Private initialization: `__init__()`

**Methods in DB class:**
- Private: `_init()`, `_conn()` (connection context manager)
- Public writes: `upsert_document()`, `insert_retrieval()`, `insert_engagement()`, `update_source_timestamp()`
- Public reads: `all_documents()`, `retrieval_counts()`, `engagement_counts()`, `all_embeddings()`

## Where to Add New Code

**New Analysis Feature (e.g., new anomaly detector):**
- Implementation: Add method to `Memento` class in `memento.py` (e.g., `get_[anomaly_name]()`)
- Query helper: If new queries needed, add read method to `DB` class in `db.py`
- Testing: Add test case in `demo.py` or create `test_memento.py`

**New Ingestion Hook (e.g., logging model confidence scores):**
- Implementation: Add method to `Memento` class in `memento.py` (e.g., `log_model_confidence()`)
- Schema: Add column/table to `SCHEMA` constant in `db.py`
- Write method: Add upsert/insert method to `DB` class in `db.py`

**New Reporting Format (e.g., JSON export):**
- Implementation: Add method to `Memento` class in `memento.py` (e.g., `to_json()`)
- Depends on: Analysis layer; no schema changes needed

**Configuration Extension (e.g., new threshold parameter):**
- Parameter: Add to `Memento.__init__()` signature in `memento.py` (line 72)
- Store as instance variable: `self.new_param = new_param`
- Use in analysis methods as needed

**Integration with External Vector Store (e.g., Chroma, Qdrant):**
- Note: README mentions future integrations but not yet implemented
- Suggested location: Create `rag_memento/integrations.py` (new file)
- Pattern: Subclass or wrapper around `Memento` to auto-capture results from specific vector DB SDKs

## Database Schema (SQLite)

Located in `db.py` lines 6-34:

**Table: documents**
- Columns: `doc_id` (PK), `filename`, `embedding_vec` (BLOB), `embedded_at` (REAL), `source_updated_at` (REAL)
- Purpose: Track corpus documents and their embeddings
- Queries: Used by all analysis methods

**Table: retrievals**
- Columns: `id` (PK), `doc_id` (FK), `query_hash`, `rank`, `score`, `retrieved_at`
- Indexes: `idx_retrievals_doc`, `idx_retrievals_time`
- Purpose: Log search events (when docs were retrieved, with rank/score)
- Queries: Used for ghost detection, suspect detection, engagement rate calculation

**Table: engagements**
- Columns: `id` (PK), `doc_id` (FK), `event_type`, `engaged_at`
- Indexes: `idx_engagements_doc`
- Purpose: Log user interactions with documents
- Queries: Used for engagement rate calculation, cleanup report
