# Milestone v1.6: Generation Trace Capture

**Status:** ✅ SHIPPED 2026-04-20
**Phases:** 24-24
**Total Plans:** 1

## Overview

Milestone v1.6 added the smallest useful generation-trace capture layer for future generation metrics. The shipped result preserves prompt/query text, retrieved context references, final answer text, and optional evaluation labels as append-only records with sync/async parity across all backends.

## Phases

### Phase 24: Generation trace capture foundation

**Goal**: Persist minimal generation-trace records for prompt, retrieved context, and final answer data with sync/async parity and no scoring logic.
**Depends on**: Phase 23
**Plans**: 1 plan

Plans:

- [x] 24-01: Add trace capture storage and read-only access for future generation metrics

**Details:**
- Added `GenerationTraceRow` and additive backend contract methods for trace insert/read.
- Implemented append-only trace storage across SQLite, Postgres, async Postgres, and in-memory backends.
- Exposed `log_generation_trace()` and `get_generation_traces()` on both `Corpulse` and `AsyncCorpulse`.
- Documented the capture-only surface and locked behavior with backend, parity, and regression tests.

## Milestone Summary

**Decimal Phases:**

- None

**Key Decisions:**

- Trace data lives in a separate append-only table so document deletion cannot rewrite evaluation history.
- SQL backends serialize list fields explicitly, while the in-memory backend keeps native Python lists.
- Deterministic ordering uses `captured_at` plus the backend row id to keep sync and async parity stable.
- The milestone stays capture-only; no generation scoring ships until a later phase.

**Issues Resolved:**

- Closed the storage contract gap for generation traces without altering retrieval or engagement methods.
- Proved append-only retention survives document deletion and backend round-trips.
- Verified sync and async facades return the same generation-trace row shape.

**Issues Deferred:**

- Generation scoring, faithfulness, context precision, and other answer-quality metrics remain deferred to a future milestone.

**Technical Debt Incurred:**

- None recorded during v1.6 closeout.
