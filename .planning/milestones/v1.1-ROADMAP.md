# Milestone v1.1: Pluggable Storage Backends

**Status:** ✅ SHIPPED 2026-04-09
**Phases:** 6-10
**Total Plans:** 10

## Overview

Milestone v1.1 made corpulse storage pluggable while keeping SQLite as the zero-configuration default. The shipped result includes a frozen storage abstraction, SQLite and in-memory backends, pooled sync and async PostgreSQL backends, and a narrow `AsyncCorpulse` integration path for async services.

## Phases

### Phase 6: Storage Foundation

**Goal**: The `StorageBackend` abstraction exists, `SQLiteBackend` preserves the regression baseline, `InMemoryBackend` enables test writing, and `Corpulse` accepts an explicit backend argument.
**Depends on**: Phase 5
**Plans**: 3 plans

Plans:

- [x] 06-01: Freeze the backend contract and add shared backend contract/core integration scaffolding
- [x] 06-02: Refactor SQLite behind the backend interface and wire explicit backend injection
- [x] 06-03: Implement `InMemoryBackend` and finish shared parity coverage

**Details:**
- Introduced `StorageBackend`, shared row contracts, and `StorageBackendError`.
- Refactored the legacy SQLite implementation into `SQLiteBackend`.
- Added `Corpulse(backend=...)` without changing the default SQLite path.
- Added `InMemoryBackend` and shared backend parity coverage.

### Phase 7: PostgresBackend (Sync)

**Goal**: A service using PostgreSQL can point corpulse at it and get the same corpus health analytics as SQLite.
**Depends on**: Phase 6
**Plans**: 1 plan

Plans:

- [x] 07-01: Implement lazy sync `PostgresBackend` with schema auto-init and `[postgres]` extra

**Details:**

- Added deterministic fake-driver tests plus env-gated live PostgreSQL coverage.
- Wired package extras and lazy import boundaries so base imports stay dependency-free.

### Phase 8: AsyncPostgresBackend

**Goal**: An async service can use corpulse with PostgreSQL without blocking the event loop.

## Milestone Summary

**Decimal Phases:**

- None

**Key Decisions:**

- Kept `Corpulse()` unchanged and made backend selection explicit via `backend=...`.
- Preserved lazy optional dependency loading for both sync and async Postgres integrations.
- Shipped a narrow `AsyncCorpulse` path for v1.1 and deferred broader async analytics parity to a later milestone.
- Treated requirement closure as evidence-gated, not implementation-gated.

**Issues Resolved:**

- Removed the hard dependency on SQLite-only persistence internals.
- Added production-usable pooled Postgres support for sync and async services.
- Closed milestone audit gaps around stale Postgres verification evidence and missing async integration proof.

**Issues Deferred:**

- Broader async analytics facade remains deferred beyond the shipped narrow `AsyncCorpulse` integration path.
- Future backend work such as MySQL/MariaDB and schema migration support remains outside v1.1.

**Technical Debt Incurred:**

- Milestone audit found one documentation-only drift item: `INT-02` was evidenced by verification artifacts before the live requirements file was aligned during archive.
