# Requirements Archive: corpulse v1.2

**Archived:** 2026-04-12
**Milestone:** v1.2 — Full Async Parity
**Outcome:** shipped

## Shipped Requirements

### v1.2 Full Async Parity

- [x] **ASYNC-PAR-01**: `AsyncCorpulse.to_dataframe(window_days)` returns a pandas DataFrame with the same columns, ordering, and status classification as sync `Corpulse.to_dataframe()`, with the same install-hint failure mode when pandas is unavailable.
- [x] **ASYNC-PAR-02**: `AsyncCorpulse.report(window_days)` returns the structured payload underlying sync `Corpulse.report()` output.
- [x] **ASYNC-PAR-03**: `AsyncCorpulse.cleanup_report()` returns the structured payload underlying sync `Corpulse.cleanup_report()` output.
- [x] **REPORT-HELPERS-01**: Structured-payload builder helpers for report and cleanup outputs live in `corpulse/core.py` and are shared by sync and async paths.
- [x] **REPORT-HELPERS-02**: Sync `Corpulse.report()` and `Corpulse.cleanup_report()` consume the shared payloads via a thin stdout formatter with unchanged behavior.
- [x] **ASYNC-TEST-01**: Deterministic async unit tests prove `AsyncCorpulse.to_dataframe()` parity against sync on identical fixture data.
- [x] **ASYNC-TEST-02**: Deterministic async unit tests prove `AsyncCorpulse.report()` and `AsyncCorpulse.cleanup_report()` parity against the shared structured payloads.
- [x] **ASYNC-TEST-03**: Live asyncpg integration tests exercise `to_dataframe`, `report`, and `cleanup_report` end-to-end against real Postgres when `CORPULSE_POSTGRES_TEST_CONNINFO` is set.
- [x] **ASYNC-DOC-01**: README documents first-class async usage via `AsyncCorpulse` and `AsyncPostgresBackend`.
- [x] **ASYNC-DOC-02**: `AsyncCorpulse` docstrings document args, returns, raises, and sync parity notes.
- [x] **ASYNC-DOC-03**: `examples/` contains a runnable async demo for ingest → analysis → report flow.

- Phase 11 created the shared helper layer that made sync/async structured parity enforceable from one code path.

- Phase 13 added the live asyncpg evidence needed to validate the async path against a real Postgres backend.
- Phase 14 completed the milestone by documenting the async API and shipping a runnable example.
- The live `.planning/REQUIREMENTS.md` file lagged behind implementation and was reconciled at archive time.
