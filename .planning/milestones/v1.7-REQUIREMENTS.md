# Requirements Archive: corpulse v1.7

**Archived:** 2026-04-22
**Milestone:** v1.7 — Generic Integration Wrapping
**Outcome:** shipped

## Shipped Requirements

### Wrapper Core

- [x] **WRAP-01**: Maintainer can wrap a synchronous retrieval client by configuring intercepted methods and a result normalizer instead of writing a dedicated proxy class from scratch.
- [x] **WRAP-02**: Maintainer can wrap an asynchronous retrieval client through the same generic API while keeping `Corpulse.log_retrieval()` execution safe for sync or async corpulse implementations.

### Compatibility

- [x] **COMP-01**: Existing Qdrant users can keep using `QdrantCorpulseClient` and `AsyncQdrantCorpulseClient` without changing current call sites or result handling.
- [x] **COMP-02**: Optional dependency behavior remains lazy so `import corpulse` still succeeds without `qdrant-client` installed.

### Extension Surface

- [x] **EXT-01**: Library users can discover and use the public `wrap()` / `WrapMethod` extension surface to build thin custom integrations for future vector database clients.

## Requirement Outcomes

- `WRAP-01` and `WRAP-02` were validated by the new generic sync/async wrapper engine and the dedicated non-Qdrant wrapper tests.
- `COMP-01` was validated by the unchanged Qdrant wrapper behavior under the existing compatibility suite.
- `COMP-02` was validated by package import tests showing optional Qdrant behavior remains lazy.
- `EXT-01` was validated by package-root exports and README guidance for the advanced adapter path.
