# Milestone v1.2: Full Async Parity

**Status:** ✅ SHIPPED 2026-04-12
**Phases:** 11-14
**Total Plans:** 7

## Overview

Milestone v1.2 closed the remaining gap between the async and sync corpulse surfaces. The shipped result includes shared structured-report helpers, `AsyncCorpulse` parity for `to_dataframe()`, `report()`, and `cleanup_report()`, live asyncpg integration coverage, and first-class async documentation plus a runnable example.

## Phases

### Phase 11: Shared Report Helpers

**Goal**: Structured-payload builder functions for the report table and cleanup-report sections live in `corpulse/core.py`, consumed by sync and async paths from the same code; sync printed output is byte-for-byte unchanged.
**Depends on**: Phase 10
**Plans**: 3 plans

Plans:

- [x] 11-01: Capture deterministic fixture baselines and pin pre-refactor stdout for `report()` and `cleanup_report()`
- [x] 11-02: Add unit tests for shared payload contracts and implement the pure helper builders in `corpulse/core.py`
- [x] 11-03: Rewire sync formatter methods through shared helpers and prove stdout and fallback behavior are unchanged

**Details:**
- Captured immutable stdout baselines for sync `report()` and `cleanup_report()`.
- Extracted pure shared payload builders used by sync and async paths.
- Refactored sync reporting surfaces to format from shared helper payloads without changing public behavior.

### Phase 12: Async Parity Methods + Unit Tests

**Goal**: `AsyncCorpulse` exposes `to_dataframe()`, `report()`, and `cleanup_report()` backed by the Phase 11 shared helpers, and deterministic async tests prove their output is at parity with sync for the same backend fixture.
**Depends on**: Phase 11
**Plans**: 2 plans

Plans:

- [x] 12-02: Implement `AsyncCorpulse.report()` and `cleanup_report()` as shared-helper payload wrappers with deterministic parity tests

**Details:**
- Added shared frozen fixture builders for sync and async parity tests.
- Implemented async dataframe export with sync-equivalent pandas guard behavior.
- Added structured-return async `report()` and `cleanup_report()` with deterministic parity tests.

**Goal**: A developer reading the README can understand and use `AsyncCorpulse` as a first-class path; all new `AsyncCorpulse` methods have API-reference-quality docstrings; a runnable script under `examples/` demonstrates the full ingest → analysis → report flow.

## Milestone Summary

**Decimal Phases:**

- None

**Key Decisions:**

- Kept shared structured-report payload builders in `corpulse/core.py` as the single source of truth for sync and async report data.
- Kept async report methods structured-return only instead of mirroring sync stdout behavior.
- Verified async parity with both deterministic frozen fixtures and env-gated live asyncpg coverage.
- Used an inline async adapter over `InMemoryBackend` for the shipped example so the default demo remains dependency-light.

**Issues Resolved:**

- Removed duplicated sync/async report assembly logic by centralizing payload builders.
- Closed the remaining async parity gaps for dataframe export and structured report surfaces.
- Added live Postgres verification for the new async methods and completed the async documentation gap.

**Issues Deferred:**

- No `v1.2` milestone audit artifact was recorded before archival; the milestone was archived by explicit user choice without that audit.
- Future milestone scope is still needed for integrations, distribution, and broader async API evolution.

**Technical Debt Incurred:**

- The milestone requirements file remained stale until archive time and was normalized during archival instead of during phase transitions.
