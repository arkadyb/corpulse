## Milestone Summary

**Key accomplishments:**

- PyPI metadata now uses Hatchling dynamic versioning, with tests enforcing the single-source version contract and required discoverability fields.
- Source and wheel artifacts include the required release files, and package tests verify built outputs when present.
- README installation instructions now lead with PyPI commands, and release artifacts pass long-description checks.
- Built wheels are verified in isolated venvs for base installs and all declared optional extras.
- Optional dependency failures now tell users exactly which `pip install corpulse[...]` command to run.
- GitHub Actions can build once, publish to TestPyPI manually, and publish tagged releases to PyPI through Trusted Publishing.
- Maintainers have documented first-release and post-publish smoke checks for both base and qdrant-extra installs.

**Key decisions:**

- Use Hatchling dynamic versioning from `corpulse/__init__.py` rather than duplicating version values.
- Keep optional integrations lazy and prove them through extras installed from built artifacts.
- Use PyPI Trusted Publishing over long-lived API tokens.
- Keep production publishing tag-gated and behind the GitHub `pypi` environment.
- Keep published-package smoke checks manual because they depend on external PyPI/TestPyPI state, but pin the exact commands in tests.

**Issues resolved:**

- Fixed the Postgres extra so clean venv installs use a binary-safe psycopg distribution.
- Reconstructed missing Phase 35 summaries from existing implementation evidence and passing tests.
- Replaced GitHub-first install wording with PyPI-first install guidance while retaining source-install fallback.

**Issues deferred:**

- External GitHub `pypi` environment reviewer configuration remains a manual release-time setup step.
- Live TestPyPI/PyPI smoke checks remain manual release-time actions documented in `.github/RELEASE_CHECKLIST.md`.
- Release note automation, signed artifacts beyond Trusted Publishing provenance, and PyPI adoption reporting are future release-maturity work.
- Three old quick-task placeholders remain acknowledged as deferred in `.planning/STATE.md`.
