<objective>
Create the release workflow foundation: CI tests the package, builds the sdist and wheel once, and uploads those exact `dist/*` artifacts for downstream publish jobs.
</objective>

<threat_model>
<assets>
- Release artifacts under `dist/`.
- GitHub Actions workflow permissions.
- The package test/build signal used before publication.
</assets>
<threats>
- MEDIUM T35-01: The build job receives OIDC publish permission even though it should only test and build.
- MEDIUM T35-02: Publish jobs later rebuild from a different checkout state instead of publishing the exact tested artifacts.
</threats>
<mitigations>
- Keep workflow-level permissions at `contents: read`.
- Do not include `id-token: write` in the build job.
- Upload `dist/*` as a named artifact after `python -m build`.
</mitigations>
</threat_model>

<action>
Create `.github/workflows/release.yml` with a workflow named `Release`.

The initial workflow must contain:
- `name: Release`
- top-level `permissions:` with `contents: read`
- `on.workflow_dispatch` so maintainers can build release artifacts manually
- `on.push.tags` with the pattern `"v*"`
- a `build` job that runs on `ubuntu-latest`
- `actions/checkout@v4`
- `actions/setup-python@v5` with `python-version: "3.12"`
- a shell step named `Install package and build tooling` that runs:
  - `python -m pip install --upgrade pip`
  - `python -m pip install ".[dev]" build`
- a step named `Run tests` that runs `python -m pytest`
- a step named `Build distributions` that runs `python -m build`
- an artifact upload step using `actions/upload-artifact@v4` with:
  - `name: python-package-distributions`
  - `path: dist/*`

Do not add any publish job in this task. Do not add `id-token: write` anywhere in the workflow yet.
</action>
