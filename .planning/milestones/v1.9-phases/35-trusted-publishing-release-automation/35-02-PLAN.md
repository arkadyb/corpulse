<objective>
Extend the release workflow so manually dispatched runs can publish the already-built artifacts to TestPyPI through PyPI Trusted Publishing and OIDC.
</objective>

<threat_model>
<assets>
- TestPyPI project publishing trust.
- GitHub Actions OIDC token permission.
- Built `python-package-distributions` artifact.
</assets>
<threats>
- MEDIUM T35-03: TestPyPI publishing uses a long-lived token or secret instead of Trusted Publishing.
- LOW T35-04: The TestPyPI trusted publisher is configured with a workflow or environment name that does not match repository automation.
</threats>
<mitigations>
- Use `pypa/gh-action-pypi-publish@release/v1` without username, password, or token inputs.
- Set `permissions.id-token: write` only on the TestPyPI publish job.
- Document the exact TestPyPI trusted publisher owner, repository, workflow, and environment values.
</mitigations>
</threat_model>

<action>
Update `.github/workflows/release.yml` with a `publish-testpypi` job.

The job must:
- be named `publish-testpypi`
- use `name: Publish to TestPyPI`
- use `runs-on: ubuntu-latest`
- declare `needs: build`
- run only for manual workflow dispatch with `if: github.event_name == 'workflow_dispatch'`
- declare `environment: testpypi`
- declare job-level permissions:
  - `contents: read`
  - `id-token: write`
- use `actions/download-artifact@v4` with:
  - `name: python-package-distributions`
  - `path: dist`
- use `pypa/gh-action-pypi-publish@release/v1`
- set `repository-url: https://test.pypi.org/legacy/`

Do not add `password`, `username`, `api-token`, `PYPI_API_TOKEN`, `TEST_PYPI_API_TOKEN`, or `__token__` anywhere in the workflow.
</action>
