<objective>
Make PyPI install commands the stable user-facing path and add a maintainer release checklist that covers version bump, build, TestPyPI validation, PyPI publish, and post-publish smoke checks.
</objective>

<threat_model>
<assets>
- User-facing installation commands in `README.md`.
- Maintainer release procedure in `.github/RELEASE_CHECKLIST.md`.
- Trusted Publishing setup in `.github/TRUSTED_PUBLISHING.md`.
</assets>
<threats>
- MEDIUM T36-01: README regresses to source-first or unpublished-package install guidance.
- HIGH T36-02: Release checklist instructs maintainers to use PyPI API tokens despite the Trusted Publishing workflow.
- MEDIUM T36-03: Release checklist omits a required release stage, causing an unvalidated PyPI publish.
</threats>
<mitigations>
- Keep exact PyPI install strings under test.
- Add checklist tests for each required release stage.
- Assert the checklist does not mention token secret names or token-based publish inputs.
</mitigations>
</threat_model>

<action>
Create `.github/RELEASE_CHECKLIST.md` as the authoritative first-release checklist.

The checklist must include sections or checklist items for these stages:
- `Version bump`
- `Build artifacts`
- `TestPyPI publish`
- `TestPyPI validation`
- `Production PyPI publish`
- `Post-publish smoke checks`

The checklist must include these exact commands or command fragments:
- `python -m build`
- `workflow_dispatch`
- `git tag v`
- `git push origin v`
- `python -m pip install --index-url https://test.pypi.org/simple/ --extra-index-url https://pypi.org/simple/ corpulse`
- `python -m pip install corpulse`
- `python -m pip install "corpulse[qdrant]"`

The checklist must state:
- `Do not create or use a PyPI API token for this workflow.`
- `Do not store PYPI_API_TOKEN, TEST_PYPI_API_TOKEN, or any PyPI password secret for this workflow.`

The checklist must tell maintainers to confirm the GitHub `pypi` environment has required reviewers or equivalent explicit approval before the first production release.

Update `.github/TRUSTED_PUBLISHING.md` to link to `.github/RELEASE_CHECKLIST.md` for the operational release steps.
</action>
