<objective>
Replace GitHub-first install messaging with PyPI-first install text and validate that built distribution metadata renders cleanly for PyPI.
</objective>

<threat_model>
<assets>
- README content rendered as PyPI long description.
- Installation instructions copied by users.
</assets>
<threats>
- LOW: stale "not yet on PyPI" docs tell users to install from GitHub after the package is published.
- LOW: README markup accepted by GitHub may fail PyPI long-description rendering.
</threats>
<mitigations>
- Add README tests for exact PyPI install commands.
- Run `python -m twine check dist/*` after build.
</mitigations>
</threat_model>

<action>
Update the README `## Installation` section so the primary install block contains exactly:

```bash
# Core library
pip install corpulse

# With Qdrant wrapper support
pip install "corpulse[qdrant]"
```

Remove the phrase `GitHub install — not yet on PyPI`. Keep a short source-install fallback after the PyPI commands:

```bash
# From source
pip install "git+https://github.com/arkadyb/corpulse.git"
```

Keep the sentence `Requires Python 3.10+. The [qdrant] extra installs qdrant-client>=1.7.` adjusted only as needed for Markdown formatting.
</action>
<acceptance_criteria>
- `README.md` contains `pip install corpulse`.

- `README.md` contains `pip install "git+https://github.com/arkadyb/corpulse.git"`.
- `README.md` does not contain `not yet on PyPI`.
- `README.md` does not contain `corpulse[qdrant] @ git+https://github.com/arkadyb/corpulse.git`.
</acceptance_criteria>
</task>
