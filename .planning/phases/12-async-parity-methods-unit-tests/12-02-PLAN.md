<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| async report methods to backend aggregates | Awaited backend rows cross into shared payload helpers and must not diverge from sync assumptions |
| async API to service callers | Service code consumes returned payload dicts directly, so stdout coupling or schema drift would break downstream integrations |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-04 | I | `corpulse/async_core.py::report` and `cleanup_report` | mitigate | Keep async report methods structured-return only and explicitly avoid `print`/`tabulate` usage so service callers do not leak report text to logs by default. |
| T-12-05 | T | `corpulse/async_core.py` payload assembly | mitigate | Build expected payloads in tests from `_build_report_summary`, `_build_report_rows`, and `_build_cleanup_payload`, then reuse those same helpers in the implementation so async and sync logic cannot drift silently. |
| T-12-06 | T | cleanup payload section math | mitigate | Assert exact `count`, `top5`, `overflow`, and metadata fields in async cleanup parity tests so section truncation and prioritization stay aligned with the Phase 11 helper contract. |
</threat_model>
