<context>
Phase 26 is the adoption and polish phase of milestone v1.7. The generic engine is already complete; this phase should focus on treating Qdrant as the first real integration built on top of it and on documenting the extension pattern accurately.

Relevant implementation facts:
- The current working tree already contains Qdrant wrappers that subclass the shared sync/async wrapper base classes.
- Existing Qdrant tests define the compatibility contract more reliably than prose documentation.
- The package root already exports the generic wrapper API; the remaining job is to align docs, behavior, and tests around that reality.
- The milestone explicitly rejects a zero-config universal wrapper claim, so the docs must keep normalization recipes explicit.

Locked design decisions for this phase:
- `QdrantCorpulseClient` and `AsyncQdrantCorpulseClient` remain public, first-class compatibility entry points.
- All Qdrant-specific behavior lives in the Qdrant module, not in the shared wrapper layer.
- The extension path is documented as an advanced maintainer-facing API, not as automatic support for arbitrary clients.
</context>
