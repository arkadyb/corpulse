<objective>
Implement the workload trace storage contract for SQLite, sync Postgres, and async Postgres while preserving existing backend behavior.
</objective>

<truths>
- This plan depends on `28-01`; do not start until model and base backend methods exist.
- Preserve schema/table-prefix behavior in Postgres backends.
- Store `components` and `timings` as JSON at the backend boundary.
</truths>

<threat_model>
Durable storage can retain sensitive request metadata. Keep raw query optional, store JSON fields exactly as supplied, and do not add implicit raw component content requirements. Existing tenant schema/table-prefix safeguards must remain intact for Postgres.
</threat_model>
