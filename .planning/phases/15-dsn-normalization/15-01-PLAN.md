<objective>
Add a single shared DSN normalization helper and wire it into both sync (`PostgresBackend`) and async (`AsyncPostgresBackend`) Postgres backends so SQLAlchemy-style DSNs like `postgresql+psycopg://...` and `postgresql+asyncpg://...` are accepted while plain DSNs remain byte-for-byte unchanged.

Purpose: Users routinely paste SQLAlchemy-style DSNs into config. Today both backends hand these to `psycopg`/`asyncpg` unchanged and fail because neither driver understands the `+driver` qualifier. A tiny, conservative prefix-strip helper fixes this without pulling in SQLAlchemy or altering any existing behavior.

Output:
- New `corpulse/backends/_dsn.py` exporting `_normalize_postgres_dsn`.
- `postgres.py` and `postgres_async.py` call the helper immediately before pool construction.
- New parametrized test file plus regression assertions on existing backend test files.
</objective>

New helper contract (corpulse/backends/_dsn.py):
```python
_SCHEME_PREFIXES = ("postgresql+", "postgres+")

def _normalize_postgres_dsn(dsn: str) -> str:
    """Strip SQLAlchemy-style '+driver' qualifier from Postgres URIs.

    - `postgresql+<driver>://rest` -> `postgresql://rest`
    - `postgres+<driver>://rest`   -> `postgres://rest`
    - Case-sensitive; only lowercase prefixes match.
    - Anything not starting with one of these prefixes (including libpq
      key=value conninfo strings) passes through byte-for-byte.
    - If a prefix matches but no `://` separator exists after the driver
      name, the input is considered malformed and passes through unchanged.
    """
```

Existing sync backend call site (corpulse/backends/postgres.py):
```python
# inside PostgresBackend.__init__
self._pool = connection_pool(
    conninfo=conninfo,            # <- wrap with _normalize_postgres_dsn(conninfo)
    min_size=min_size,
    max_size=max_size,
    kwargs={"row_factory": dict_row},
    open=True,
)
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller -> backend constructor | The DSN string crosses from application/config code into backend init. It originates from application configuration, not end-user request input. |
| backend -> driver (psycopg / asyncpg) | Normalized DSN is handed to the driver, which performs its own URI parsing and validation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | Information Disclosure | `_normalize_postgres_dsn` and call sites | accept | The helper performs a pure in-memory string transform and does not log the DSN. No new logging is added at either backend call site (RESEARCH Open Question 1 — explicitly deferred). Credentials embedded in the DSN therefore never reach logs via this phase. |
| T-15-02 | Tampering | Malformed `+driver` qualifier input | mitigate | The helper only rewrites when a recognized lowercase prefix (`postgresql+` / `postgres+`) matches AND a `://` separator exists after the driver name. Malformed inputs fall through unchanged, so the driver's own parser surfaces the error in its normal path. Parametrized unit test covers the "prefix matches but no `://`" case. |
| T-15-03 | Denial of Service | DSN parsing | accept | Transform is O(n) on the DSN length with a bounded prefix check and a single `find`. No regex backtracking, no recursion, no network calls. |
| T-15-04 | Spoofing / Elevation / Repudiation | — | N/A | Not applicable: internal pure string helper with no identity, authz, or audit surface. |
</threat_model>
