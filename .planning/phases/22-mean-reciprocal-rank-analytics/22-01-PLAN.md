<context>
The current milestone intentionally favors metrics that can be derived from stored retrieval and engagement data with no new schema or ingestion surface.

Relevant implementation facts:
- `Corpulse.log_retrieval()` already records retrieval rows and query attempts.
- `retrieval_counts(since)` returns per-document retrieval aggregates with `cnt`, `avg_rank`, and `avg_score`.
- `engagement_counts(since)` returns per-document engagement counts.
- All backends already expose the same aggregate surfaces across SQLite, Postgres, async Postgres, and in-memory implementations.
- Phase 21 already added query-level metrics for low-confidence and zero-result analysis, so Phase 22 should not re-open that scope.

The metric definition must be explicit in tests because the schema does not store query-relevance labels. The chosen Phase 22 proxy is document-level:
- join retrieval aggregates and engagement counts on `doc_id`
- treat documents with at least one engagement as relevant
- compute reciprocal rank from each matched document's average retrieval rank
- return the arithmetic mean of those reciprocal ranks
- return `0.0` when no matched documents exist
</context>
