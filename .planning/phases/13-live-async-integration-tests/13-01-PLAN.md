## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| environment variable to live database fixture | `CORPULSE_POSTGRES_TEST_CONNINFO` points tests at a mutable PostgreSQL database that the fixture truncates before and after each test |
| shared fixture rows to real database state | Canonical seed rows cross from deterministic in-memory helpers into a real Postgres round trip where drift or partial inserts would invalidate parity evidence |
| live async payloads to verification commands | The executor’s commands must respect the shared database as a sequential resource to avoid cross-test contamination |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | T | `tests/conftest.py` live async fixture and DSN usage | mitigate | Keep the live path env-gated through `CORPULSE_POSTGRES_TEST_CONNINFO`, continue truncating only the dedicated test tables before and after each live test, and document the expected test-only DSN in the plan and verification commands. |
| T-13-02 | D | Shared Postgres database used by live async suites | mitigate | Require sequential execution of live `tests/test_async_postgres_backend.py` and `tests/test_async_core_integration.py` commands because research verified cross-test contamination when both suites hit the same DSN in parallel. |
| T-13-03 | T | `tests/test_async_core_integration.py` live assertions | mitigate | Derive live expectations from `tests/report_fixtures.py` helper builders instead of ad hoc literals so the real asyncpg evidence stays aligned with the already-shipped parity contract. |
