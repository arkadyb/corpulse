# Plan 31-02 - Context Reuse and Retrieval Overlap

## Goal

Extend the session report helper with deterministic repeated-context signals inside each session.

## Must Haves

- Reuse is derived only from refs and content hashes.
- Reuse is counted within a session only, never across sessions.
- Reuse count is based on distinct requests, not repeated components in one request.
- `system_prompt`, `user_input`, and `chat_history` are excluded from context reuse rows.
- Rows are deterministic and sorted.

  <action>
    Extend `_build_session_report(traces)` to populate `context_reuse`.

    Required row fields:
    - `session_id`
    - `component_type`
    - `reuse_key`
    - `first_seen_at`
    - `request_count`
    - `reuse_count`

    For each session, compute the set of `(component_type, reuse_key)` values per request. Include a row only when the value appears in two or more distinct requests in the same session. Set `reuse_count = request_count - 1`, and `request_share = round(request_count / session_request_count, 4)`.

    Sort rows by `session_id`, `component_type`, `reuse_key`.
  </action>
