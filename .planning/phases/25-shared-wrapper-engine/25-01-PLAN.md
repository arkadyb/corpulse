<context>
Phase 25 is the abstraction phase of milestone v1.7. It should produce the reusable engine that future integrations will build on, but it should not try to make result normalization fully automatic.

Relevant implementation facts:
- The validated spike already proved a shared engine is feasible and that the main variability lies in response normalization.
- Existing Qdrant wrappers use composition and transparent delegation, which is the correct shape to preserve.
- `Corpulse.log_retrieval()` is the stable write boundary that wrapper integrations should target.
- Lazy optional-dependency behavior is already part of the package contract and must remain unchanged.

Locked design decisions for this phase:
- The public surface is one generic `wrap()` API plus an explicit method-spec abstraction.
- Sync and async client support should share configuration shape and differ only in invocation strategy.
- The generic layer must remain free of Qdrant-specific assumptions such as `.points`, payload keys, or vector schema handling.
- A clear boundary must remain between wrapper orchestration and integration-specific normalization logic.
</context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream client response -> generic normalizer | Native client result shapes are untrusted by the generic layer and must be normalized explicitly before reaching Corpulse |
| wrapper engine -> Corpulse logging API | The wrapper layer must call `log_retrieval()` safely across sync and async variants without semantic drift |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01 | Tampering | generic abstraction boundary | mitigate | Keep result-shape extraction inside explicit normalizers; do not bake Qdrant assumptions into the engine |
| T-25-02 | Denial of Service | sync wrapper calling async logger incorrectly | mitigate | Detect awaitables in sync mode and fail clearly; use async-safe logging path in async mode |
| T-25-03 | Information Disclosure | optional dependency boundary | mitigate | Keep generic wrapper exports dependency-agnostic and retain lazy import behavior for optional integrations |
</threat_model>
